# SiPush — Obsidian ↔ 思源笔记 双向同步插件

**V1.1.0** — 纯 JS 编写，零构建，直接放入插件目录即可使用。

## 功能一览


| 功能               | 说明                                           |
| ---------------- | -------------------------------------------- |
| **推送控制台**        | 单一入口：推送 / 同步 / 暂停继续 / 失败队列 / 进度条             |
| **树状勾选推送**       | 按文件夹树勾选笔记，只推选中的部分                            |
| **一键全库推送**       | 遍历 Vault 全部 Markdown，建立关联并推送                 |
| **文件夹 / 当前笔记推送** | 按范围推送；推送为覆盖更新                                |
| **可暂停任务**        | 推送可暂停、继续、从指定位置重推、取消                          |
| **失败队列**         | 失败项入库，可重试 / 导出；可返回控制台                        |
| **媒体资源**         | 图片 / PDF / 音视频 / Office / 压缩包等引用附件自动上传       |
| **双链**           | `[[笔记]]` 转为思源块引用 `((id "锚文本"))`，目标笔记推送后可打开   |
| **双向同步**         | 对比内容哈希，自动 push / pull / 跳过                   |
| **冲突处理**         | 双方都改时：弹窗询问 / Obsidian 优先 / 思源优先              |
| **搜索拉回**         | 从思源搜索已关联文档，拉回 Obsidian                       |
| **深度压平**         | 超过思源文档深度限制时自动压平路径，避免创建失败                     |
| **文末关联 ID**      | `si-push · id:…` 写在笔记最底部极小字，不占顶部 frontmatter |


## 安装

1. 将本目录放入 Obsidian 插件目录（文件夹名建议与 manifest id 一致）：
  `.obsidian/plugins/obsidian-si-push/`
2. Obsidian → 设置 → 第三方插件 → 启用 SiPush
3. 在插件设置中配置：
  - 思源服务器地址（默认 `http://127.0.0.1:6806`）
  - API Token（思源设置 → 关于 → API Token）
  - 默认笔记本（打开设置时自动加载，也可点「刷新」）

## 使用

### 推送控制台（推荐入口）

左侧功能区只保留 **一个云图标** ☁️，点击打开 **SiPush 推送控制台**。  
底部状态栏点击同样打开控制台。

控制台内包含：


| 分区            | 能力                                  |
| ------------- | ----------------------------------- |
| **进度区**       | 实时进度条、百分比、当前文档、成功/失败数（约 0.4s 刷新）    |
| **开始推送**      | 树状勾选 / 一键全库 / 选择文件夹 / 当前文件夹 / 仅当前笔记 |
| **同步**        | 同步当前笔记 / 全库双向同步 / 按设置一键同步           |
| **任务控制**      | 暂停 / 继续 / 从指定位置重推 / 取消              |
| **失败队列 / 其它** | 失败队列、重试、搜索拉回、迁移 ID、测试连接             |


说明：

- 从控制台开始推送时，**控制台保持打开**，可实时跟进进度。
- 查看失败队列后，可用 **「← 返回推送控制台」** 回到。
- 同步报告弹窗同样可返回控制台。

### 推送 vs 同步


|     | **推送**                  | **双向同步**       |
| --- | ----------------------- | -------------- |
| 行为  | 以 Obsidian 为准 **覆盖** 思源 | 比哈希，相同则跳过      |
| 方向  | 只 Obsidian → 思源         | 可能 push 或 pull |
| 适用  | 首次迁移、强制更新、勾选推送          | 日常增量、两边都可能改    |


### 资源与双链规则

1. **引用资源自动上传**（无需在树里勾选附件文件）
  推送某篇 Markdown 时，会扫描正文中的本地引用并上传，例如：
  - `![[xxx.png]]` / `![[xxx.pdf]]` / `![[xxx.mp3]]` / `![[xxx.mp4]]` / `![[xxx.docx]]` / `![[xxx.zip]]`
  - `[[xxx.pdf]]` / `[[资料.rar]]`（无感叹号的附件双链）
  - `![](xxx.png)`、`[附件](xxx.pdf)`、`[压缩包](xxx.7z)`
2. 上传后按类型改写：
  - 图片 / 音频 / 视频 → `![](assets/...)`，便于思源内预览或播放
  - PDF / Office / 压缩包 / 其它 → `[名称](assets/...)`
  - 统一存到思源 `/assets/`（不用 `sipush` 子目录，避免引用失效）
  - 文件名去空格、缩短并加短哈希，避免 `%20` / 超长路径导致找不到
3. **同一资源被多篇引用**：同一次推送任务内只上传一次（内存缓存），后续复用同一 `assets/...` 路径。
4. **双链笔记**：`[[笔记名]]` / `[[笔记名|别名]]` 转为思源 `((docId "锚文本"))`。
  全库推送分两遍：先建文档，再写双链。被引用笔记也需推到思源后才能点开。
5. 远程 `http(s)://` 链接不下载，保持原样。

### 关联机制

关联 ID 写在笔记 **文末极小字**（不进顶部 frontmatter）：

```html
<div class="sipush-meta">si-push · id:si1y7z8a3b2c1d</div>
```

- 同一 ID 写入思源文档属性 `custom-si-push-id`，用于双向关联。
- 推送到思源时会去掉文末标记，避免污染思源正文。
- 旧笔记顶部的 `custom-si-push-id` 可一键迁移到文末（控制台 / 命令「迁移关联 ID 到文末」）。

### 同步策略（双向同步）

1. **内容相同** → 跳过
2. **仅 Obsidian 更新** → 推送到思源（含资源 / 双链预处理）
3. **仅思源更新** → 拉取到 Obsidian
4. **同时修改** → 按冲突策略处理

冲突策略（设置中可选）：

- 弹窗让用户选择（默认）
- 始终保留 Obsidian 版本
- 始终保留思源版本

### 失败队列与可暂停任务

- 推送失败会进入 **失败队列**，修好配置或深度问题后可一键重试。
- 大库推送支持 **暂停 / 继续 / 从指定位置重推 / 取消**。
- 控制台顶部可实时查看进度；异常退出后若任务停在 running，会自动改为暂停以便继续。

### 文档深度

思源文档树深度有限制（通常第 7 层下不能再建子文档）。  
插件默认按 **最大深度 6** 压平超深路径，减少创建失败。可在设置中调整。

## 思源文档结构

默认保留 Obsidian 文件夹结构（可在设置关闭）：

```
/Obsidian/
├── 工作笔记/
│   └── 工作日报/
│       └── 2026/
│           └── 2026年.md
└── ...
```

每个文档带有以下属性：

- `custom-si-push-id` — 关联 ID  
- `si-push-content-hash` — 内容哈希  
- `si-push-mtime` — 最后修改时间戳

| 设置                        | 说明                                |
| ------------------------- | --------------------------------- |
| 思源服务器 / API Token / 默认笔记本 | 连接配置                              |

## 注意

- 使用前请确认思源已启动，且 API Token、笔记本配置正确。  
- 首次全库迁移建议用「一键全库推送」或控制台全库推送。  
- 改完插件代码后需在 Obsidian 中 **重载插件** 才生效。  
- 插件目录内的旧版 `.zip` 安装包仅为备份，删除不影响运行。
