# SiPush — Obsidian ↔ 思源笔记 双向同步插件

**V1.1.0** — 纯 JS 编写，零构建，直接放入插件目录即可使用。

## 功能一览


| 功能               | 说明                                                         |
| ---------------- | ---------------------------------------------------------- |
| **推送控制台**        | 单一入口：推送 / 同步 / 暂停继续 / 失败队列 / 资源清理 / 实时进度条                 |
| **后台推送**         | 关闭控制台**不会**暂停；任务继续跑，再打开即可看最新进度                             |
| **树状勾选推送**       | 按文件夹树勾选笔记，只推选中的部分                                          |
| **一键全库推送**       | 遍历 Vault 全部 Markdown，建立关联并推送（先上传正文，再写双链）                   |
| **文件夹 / 当前笔记推送** | 按范围推送；推送为覆盖更新                                              |
| **可暂停任务**        | 推送可暂停、继续、从指定位置重推、取消；异常退出后自动改为暂停以便续跑                      |
| **失败队列**         | 失败项入库，可重试 / 导出；升级后会从历史同步报告自动导入失败项                          |
| **媒体资源**         | 任意非 md 本地引用（图片 / PDF / 音视频 / Office / 压缩包等）自动上传            |
| **附件去重索引**       | `asset-index.json` 按内容 SHA-256 复用已上传资源，避免多份副本               |
| **资源池去重**        | 扫描思源 `/assets/`，同内容/同族副本只留最早一份，并改写引用                         |
| **音视频修复**        | 把误写成 `![](assets/xxx.mp3)` 的引用改成 `<audio>` / `<video>` 播放器 |
| **双链**           | `[[笔记]]` 转为思源块引用 `((id "锚文本"))`，目标笔记推送后可打开                 |
| **双向同步**         | 对比内容哈希，自动 push / pull / 跳过                                 |
| **冲突处理**         | 双方都改时：弹窗询问 / Obsidian 优先 / 思源优先                            |
| **搜索拉回**         | 从思源搜索已关联文档，拉回 Obsidian                                     |
| **深度压平**         | 超过思源文档深度限制时自动压平路径（`a__b__c`），避免创建失败                       |
| **路径校正**         | 改前缀/深度后重推，自动把已有文档迁到正确层级                                    |
| **文末关联 ID**      | `si-push · id:…` 写在笔记最底部极小字，不占顶部 frontmatter                |


## 安装

1. 将本目录放入 Obsidian 插件目录（文件夹名建议与 manifest id 一致）：
  `.obsidian/plugins/obsidian-si-push/`
2. Obsidian → 设置 → 第三方插件 → 启用 SiPush
3. 在插件设置中配置：
  - 思源服务器地址（默认 `http://127.0.0.1:6806`）
  - API Token（思源设置 → 关于 → API Token）
  - 默认笔记本（打开设置时自动加载，也可点「刷新」）

> `data.json` 为运行时配置（含 Token / 路径），请勿提交到公开仓库；可参考 `data.json.example`。

## 使用

### 推送控制台（推荐入口）

左侧功能区只保留 **一个云图标** ☁️，点击打开 **SiPush 推送控制台**。  
底部状态栏点击同样打开控制台。

控制台内包含：


| 分区            | 能力                                              |
| ------------- | ----------------------------------------------- |
| **进度区**       | 实时进度条、百分比、当前文档、成功/失败数（约 0.4s 刷新）；区分「上传 / 双链」两阶段 |
| **开始推送**      | 树状勾选 / 一键全库 / 选择文件夹 / 当前文件夹 / 仅当前笔记             |
| **同步**        | 同步当前笔记 / 全库双向同步 / 按设置一键同步                       |
| **任务控制**      | 暂停 / 继续 / 从指定位置重推 / 取消                          |
| **失败队列 / 其它** | 失败队列、重试、搜索拉回、迁移 ID、去重资源池、修复音视频、测试连接             |


说明：

- 点「关闭（后台继续推送）」只关窗口，**不会暂停**正在进行的任务。
- 从控制台开始推送时，控制台可保持打开实时跟进；关掉再开也能接上进度。
- 查看失败队列 / 同步报告后，可用 **「← 返回推送控制台」** 回去。

### 推送 vs 同步


|     | **推送**                  | **双向同步**       |
| --- | ----------------------- | -------------- |
| 行为  | 以 Obsidian 为准 **覆盖** 思源 | 比哈希，相同则跳过      |
| 方向  | 只 Obsidian → 思源         | 可能 push 或 pull |
| 适用  | 首次迁移、强制更新、勾选推送          | 日常增量、两边都可能改    |


### 资源与双链规则

1. **引用资源自动上传**（无需在树里勾选附件文件）  
   推送某篇 Markdown 时，会扫描正文中的本地引用；**任意非 `.md` 本地文件**都会上传，例如：
  - `![[xxx.png]]` / `![[xxx.pdf]]` / `![[xxx.mp3]]` / `![[xxx.wav]]` / `![[xxx.mp4]]` / `![[xxx.docx]]` / `![[xxx.zip]]`
  - `[[xxx.pdf]]` / `[[资料.rar]]`（无感叹号的附件双链）
  - `![](xxx.png)`、`[附件](xxx.pdf)`、`[录音](uuid.wav)`
2. 上传后按类型改写：
  - **图片** → `![名称](assets/...)`
  - **音频 / 视频** → `<audio controls …>` / `<video controls …>`（不要用 `![]()`，否则思源当图片加载会显示「找不到」）
  - **PDF / Office / 压缩包 / 其它** → `[名称](assets/...)`
  - 统一存到思源 `/assets/`（不用 `sipush` 子目录，避免引用失效）
  - 文件名去空格、缩短并加短哈希，避免 `%20` / 超长路径导致找不到
3. **同一资源被多篇引用 / 多次推送**：写入插件目录 `asset-index.json`（内容 SHA-256 → 思源路径）。同哈希直接复用最早那份，同步过程中就不会再堆副本。可在设置中查看索引条数或清空。
4. **已产生的多份副本**：控制台 / 命令「去重思源资源池」可事后清理（只删重复副本，不会因「未被引用」删掉独立文件）。
5. **已误写成图片语法的音视频**：控制台 / 命令「修复思源音视频引用」。
6. **大附件**（如会议录音数十 MB）：上传失败会写入推送报告「附件失败」，不再静默跳过。
7. **双链笔记**：`[[笔记名]]` / `[[笔记名|别名]]` 转为 `((docId "锚文本"))`。  
   全库推送分两阶段：先上传正文建文档，再统一写双链。被引用笔记也需推到思源后才能点开。
8. 远程 `http(s)://` 链接不下载，保持原样。

### 关联机制

关联 ID 写在笔记 **文末极小字**（不进顶部 frontmatter）：

```html
<div class="sipush-meta">si-push · id:si1y7z8a3b2c1d</div>
```

- 同一 ID 写入思源文档属性 `custom-si-push-id`，用于双向关联。
- 推送到思源时会去掉文末标记，避免污染思源正文。
- 旧笔记顶部的 `custom-si-push-id` 可一键迁移到文末（控制台 / 命令「迁移关联 ID 到文末」）。

### 同步策略（双向同步）

1. **内容相同** → 跳过
2. **仅 Obsidian 更新** → 推送到思源（含资源 / 双链预处理）
3. **仅思源更新** → 拉取到 Obsidian
4. **同时修改** → 按冲突策略处理

冲突策略（设置中可选）：

- 弹窗让用户选择（默认）
- 始终保留 Obsidian 版本
- 始终保留思源版本

### 失败队列与可暂停任务

- 推送失败会进入 **失败队列**，修好配置或深度问题后可一键重试。
- 大库推送支持 **暂停 / 继续 / 从指定位置重推 / 取消**。
- 关闭控制台不会中断任务；进度条区分「上传」与「双链」两阶段。
- 异常退出后若任务停在 running，会自动改为暂停以便继续。
- 升级插件后若发现历史同步报告里有失败项，会自动导入失败队列。

### 文档深度

思源文档树深度有限制（叶子文档最深约第 7 层，其下不能再建子文档）。  
插件默认 **最大深度 7**。超过时会把中间目录压进文档名（`a__b__c`），看起来就像层级乱了。

**默认路径前缀**也会影响层级：

- `/`：笔记本根下直接对应 Obsidian 文件夹（深层笔记更不容易被压平）
- `/Obsidian/`：全部建在「Obsidian」文档下（与早期默认一致，但会少占一层可用深度）

改前缀或深度后，打开「自动校正文档路径」再推送一次，会把已有文档迁到新路径。

## 思源文档结构

默认保留 Obsidian 文件夹结构（可在设置关闭）。前缀为 `/` 时：

```
笔记本根/
├── 工作笔记/
│   └── 工作日报/
│       └── 2026/
│           └── 2026年.md
└── ...
```

前缀为 `/Obsidian/` 时，上述结构会整体落在 `Obsidian/` 下。  
每个文档带有以下属性：

- `custom-si-push-id` — 关联 ID  
- `si-push-content-hash` — 内容哈希  
- `si-push-mtime` — 最后修改时间戳

## 主要设置项


| 设置                        | 说明                                |
| ------------------------- | --------------------------------- |
| 思源服务器 / API Token / 默认笔记本 | 连接配置                              |
| 冲突解决策略                    | ask / obsidian-wins / siyuan-wins |
| 一键同步动作                    | 全库推送 / 仅当前笔记                      |

| 自动校正文档路径                  | 路径规则变化后重推时迁移到正确层级                 |
| 同步媒体与附件                   | 推送时自动上传引用资源                       |
| 附件哈希索引                    | 查看/清空 `asset-index.json` 去重缓存     |
| 去重思源资源池 / 修复音视频引用         | 与控制台同能力，设置页也可入口                   |
| 转换双链                      | 推送时转换 `[[笔记]]`                    |
| 资源上传目录                    | 建议 `/assets/`                     |


## 注意

- 使用前请确认思源已启动，且 API Token、笔记本配置正确。  
- 首次全库迁移建议用「一键全库推送」或控制台全库推送。  
- 改完插件代码后需在 Obsidian 中 **重载插件** 才生效。  
- 插件目录内的旧版 `.zip` 安装包仅为备份，删除不影响运行。  
- 请勿把含真实 Token 的 `data.json` 提交到公开仓库。
