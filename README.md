# SiPush — Obsidian ↔ 思源笔记 双向同步插件

**V2.1** — 纯 JS，零构建，放入插件目录即可使用。

把 Obsidian 仓库推到思源：保留文件夹结构、上传引用附件、把 `[[笔记]]` 转成可点击双链，并支持**增量推送**与**定时自动同步**。

---

## 功能一览

| 功能 | 说明 |
| --- | --- |
| **推送控制台** | 单一入口：增量 / 全库 / 树选 / 暂停继续 / 失败队列 / 进度条 |
| **⚡ 增量推送** | 只推**新文档**和**有改动**的笔记，跳过未改内容 |
| **⏱ 自动增量** | 按间隔（1 / 20 / 30 / 60 分钟等，可自由设置）自动检查并推送 |
| **离线待同步队列** | 思源没开时先把变更记入队列，连上后再推 |
| **树状勾选推送** | 按文件夹树勾选，只推选中部分 |
| **一键全库推送** | 遍历 Vault 全部 Markdown（首次迁移用） |
| **立刻暂停 / 取消** | 最高优先级：马上落盘暂停，并打断卡住的网络请求 |
| **双链两阶段** | 先上传文档，再写 `((文档ID "锚文本"))`，思源可点击、有反向链接 |
| **仅回写双链** | 上传中断后，可单独把双链补写完，不必重传全文 |
| **媒体资源** | 图片 / PDF / 音视频 / Office / 压缩包等引用附件自动上传 |
| **资源去重** | 按内容哈希复用；可事后清理思源 assets 重复副本 |
| **断链 / 音视频修复** | 去重后改引用；`![](音频)` 改成可播放写法 |
| **推送收尾自动修复** | 全库/增量推完后可选自动修音视频与附件断链 |
| **双向同步** | 对比内容哈希，自动 push / pull / 跳过 |
| **冲突处理** | 双方都改：弹窗 / Obsidian 优先 / 思源优先 |
| **失败队列** | 失败项入库，可重试 / 导出 |
| **文末关联 ID** | `si-push · id:…` 在笔记最底部极小字，不占顶部 frontmatter |

## 安装

1. 将本目录放入 Obsidian 插件目录（与 `manifest.json` 的 `id` 一致即可）：  
   `.obsidian/plugins/obsidian-si-push/`  
   （本仓库里文件夹名可能是 `obsidian-si-push-main`，以你实际启用的为准。）
2. Obsidian → 设置 → 第三方插件 → 启用 **SiPush - 思源同步**
3. 设置里填写：
   - **思源服务器地址**（默认 `http://127.0.0.1:6806`）
   - **API Token**（思源 → 设置 → 关于 → API Token）
   - **默认笔记本**（打开设置会自动加载，也可点「刷新」）

> 同步依赖思源 **Kernel API**。本机默认用法下需要思源已启动；若填远程/常开的思源服务地址，本机可以不打开思源桌面。

改完 `main.js` 后，在 Obsidian 里 **重载插件** 才会生效。

## 快速教程（推荐流程）

### 第一次：全库迁到思源

1. 打开思源，确认 Kernel 可访问（设置里点「测试连接」）。
2. 左侧点云图标 ☁️ → 打开 **推送控制台**。
3. 点 **一键全库推送**（首次迁移不要用增量）。
4. 等待进度走完三个阶段：
   - **上传文档**（附件一并上传）
   - **写入双链**（`[[笔记]]` → `((id "锚文本"))`）
   - **收尾修复**（音视频 / 断链，若开启）
5. 到思源里点几条双链，确认能跳转。

首次全库可能较久，可随时 **立刻暂停**，之后 **继续**；不要中途以为「没任务」就关掉不管——上传中断时双链阶段可能还没跑。

### 之后几天：只同步新写的 / 改过的

**方式一：手动增量（最稳）**

1. 控制台点 **⚡ 增量推送（仅新/变更）**  
   或命令面板：`增量推送到思源（仅新文档/有改动）`
2. 没有变更时会提示「没有需要同步的…」。
3. 有变更时只推那几篇，并再跑双链。

**方式二：自动增量（省事）**

1. 设置 → SiPush → **增量 / 自动同步**
2. 打开 **开启自动增量同步**
3. **自动同步间隔（分钟）** 随便填，例如：
   - `1` = 每 1 分钟  
   - `20` / `30` = 每 20 / 30 分钟  
   - `60` = 每 1 小时  
   - 范围：最少 1，最多 1440（24 小时）
4. 建议保持 **监听新建/保存** 开启：改笔记会进待同步队列，到点一并推。
5. 可点 **立刻跑一次自动增量**，不用等下一个周期。

### 思源没打开时

1. 照常在 Obsidian 里写笔记。  
2. 插件会把变更放进 **待同步队列**（状态栏会显示「待推 N」）。  
3. 打开思源后：
   - 点一次 **增量推送**，或  
   - 等自动同步到点（若已开启）。

> 本机思源完全退出且 Kernel 停掉时，**当时推不上去**；只能入队，连上后再推。若希望「电脑关着思源也能推」，请把服务器地址改成一台常开的思源（NAS / Docker / 另一台机器）。

### 日常单篇

- 控制台 **仅当前笔记**，或命令「仅推送当前笔记到思源」。  
- 一键云图标默认是 **增量推送**（可在设置里改成全库 / 仅当前）。

## 推送控制台

左侧只保留一个云图标；底部状态栏点击同样打开控制台。

| 分区 | 能力 |
| --- | --- |
| **进度区** | 进度条、当前文档、成功/失败/跳过；待同步队列与自动增量状态 |
| **开始推送** | ⚡ 增量 · 树状勾选 · 全库 · 文件夹 · 当前文件夹 · 仅当前笔记 |
| **同步** | 同步当前 · 全库双向同步 · 按设置一键同步 |
| **任务控制** | ⏸ 立刻暂停 · ▶️ 继续 · 从指定位置重推 · 🔗 仅回写双链 · ⏹ 立刻取消 |
| **失败队列 / 其它** | 失败队列、重试、搜索拉回、迁移 ID、资源去重、断链/音视频修复、测试连接 |

说明：

- 从控制台开始推送时，控制台可保持打开看进度；**关掉窗口不会暂停**后台任务。  
- **立刻暂停 / 立刻取消**：马上把任务标为暂停并打断进行中的上传请求，不必等当前大附件传完。  
- 取消后任务仍可 **继续**；已上传部分不会回滚。双链未写完时可用 **仅回写双链**。

## 增量推送原理（A）

1. 本地维护 **推送索引**（`pushIndex`：路径 → mtime / size / 内容哈希 / pushId）。  
2. 首次点增量时：给「已有关联 ID」的笔记建索引，避免误把整库当成待推。  
3. 之后扫描：
   - 没有索引 / 新建笔记 → **要推**  
   - mtime 或 size 变了 → **要推**  
   - 未变 → **跳过**  
4. 推送时若内容哈希与索引一致，再次跳过实际上传。  
5. 成功推送后更新索引。

适合：全库迁完之后，过几天写了一批新日报，只想同步新的。

状态栏示例：`同步到思源 · 自动30分 · 待推3`

## 双链说明

推送分两阶段（全库 / 增量任务均如此）：

1. **上传**：正文进思源（此时可能仍是 `[[笔记]]`，思源里不一定能点）。  
2. **写入双链**：改成 `((文档ID "显示名"))`，才能点击跳转并产生反向链接。

若上传中断：

- 控制台会提示「双链尚未写入」  
- 点 **继续** 跑完，或点 **仅回写双链**

设置里可开关「改写双链」。命令：`仅回写双链到思源（不重传正文附件）`。

## 资源与附件

推送 Markdown 时会扫描正文引用并上传，例如：

- `![[a.png]]` `![[a.pdf]]` `![[a.mp3]]` `![[a.mp4]]` `![[a.docx]]`
- `[[a.pdf]]`（无 `!` 的附件双链）
- `![](a.png)`、`[文档](a.docx)`

规则摘要：

| 类型 | 写入思源的形式 |
| --- | --- |
| 图片 | `![](assets/...)` |
| 音频 / 视频 | `<audio>` / `<video>`（不要用 `![]()`，否则思源当图片显示「找不到」） |
| PDF / Office / 其它 | `[名称](assets/...)` |

- 统一目录建议 `/assets/`。  
- 同内容哈希会复用，减少重复副本（`asset-index.json`）。  
- 已堆重复副本：控制台 / 命令 **去重思源资源池**。  
- 去重后打不开：再点 **修复附件断链**。  
- 误写成图片语法的音视频：**修复思源音视频引用**。  
- 推送结束可自动做上述修复（设置「推送后自动修复」）。

## 推送 vs 双向同步 vs 增量

| | **全库/范围推送** | **增量推送** | **双向同步** |
| --- | --- | --- | --- |
| 方向 | 仅 Obsidian → 思源（覆盖） | 仅 Obsidian → 思源 | 可能 push 或 pull |
| 范围 | 指定列表 / 全库 | 仅新文档与有改动 | 扫描后按哈希决定 |
| 适用 | 首次迁移、强制对齐 | **日常写新笔记** | 两边都可能改同一篇 |

冲突策略（双向同步时）：弹窗 / 始终 Obsidian / 始终思源。

## 关联 ID

写在笔记**文末极小字**（推送到思源时会剥掉，不污染正文）：

```html
<div class="sipush-meta">si-push · id:si1y7z8a3b2c1d</div>
```

思源文档属性：

- `custom-si-push-id` — 关联 ID  
- `si-push-content-hash` — 内容哈希  
- `si-push-mtime` — 修改时间戳  

旧笔记顶部 frontmatter 里的 ID：命令 **迁移关联 ID 到文末**。

## 常见问题

**Q：增量会不会漏推？**  
按本地 mtime/size/哈希判断。改过内容一般会推。若怀疑漏了，对该笔记「仅推送当前笔记」，或再跑一次全库推送对齐。

**Q：点了暂停/取消没反应？**  
请用控制台里的 **立刻暂停 / 立刻取消**（或对应命令），并确认已重载最新插件。大附件上传会被 Abort 打断。

**Q：思源里双链点不了？**  
多半是只跑完上传、没跑「写入双链」。点 **继续** 或 **仅回写双链**。

**Q：音频显示「找不到」？**  
别用图片语法；用插件推送（会写成播放器）或跑「修复思源音视频引用」。

**Q：附件很多重复？**  
「去重思源资源池」→ 必要时「修复附件断链」。

## 注意

- 首次迁移用 **全库推送**；日常用 **增量** 或 **自动增量**。  
- 本机默认同步需要思源 Kernel 在线；离线只会入队。  
- 改插件代码后务必 **重载插件**。  
- 目录内旧 `.zip` 仅为备份，删除不影响运行。
